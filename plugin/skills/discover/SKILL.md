# Discover

Find out what exists before anyone designs anything. Every fact this session writes cites a source in `sources.md`.

1. Run the steps in `${CLAUDE_PLUGIN_ROOT}/references/START.md` with mode `discover`, including its step that asks once for the initiative's short name. Read the Discover row of `${CLAUDE_PLUGIN_ROOT}/references/MODES.md`.
2. List the files in `.inbox/` and the rows in `sources.md`. Also grep earlier session records for `to fetch:` captures, and ask the user whether each document has arrived: one that has goes in the register below, and one that has not stays an unknown. Add a row for each new document: `ID | Title | Owner | Date | Kind | Location`. `Kind` is `exists` for a document that describes what runs today, and `intends` for a plan, deck or roadmap. A local clone of a code repository is `Kind: repo`, with Location `<url>@<sha>` from `git -C <clone> remote get-url origin` (strip any `user:token@` part: a token in a clone URL must not reach a page) and `git -C <clone> rev-parse HEAD`. A file that lives only in `.inbox/` has Location `local only`.
3. Show the register and ask the user to rank it and cut what is not worth reading. Propose a `Kind` for each source it keeps, and ask the lead in plain words whether it describes what runs today or what someone plans, then record the word the file uses. Do not move on until every kept source has a confirmed `Kind`, unless the user says to: then say once that an unconfirmed `Kind` can turn a plan into a fact, write the source's `Kind` as you proposed it, and record the override as `START.md` says. Read only the top-ranked sources. Before the user cuts a source, say which other sources cover the same area: sources that describe the same systems, teams or plans are worth reading together, because a clash between them only shows when both are read.
4. Show "Here's what I think exists" as a numbered list, in groups of about five when it is longer than seven lines. Label every line with its source (the document's title in what the lead reads; the file holds `SRC-nn` and that source's `Kind`) and say whether that source describes what runs today or a plan. Before anything is written, say aloud any pair of lines you can see disagreeing: a disagreeing pair becomes one unknown naming both sides, never two facts. Write nothing to a page yet. Write only the lines the lead said yes to, as `START.md` defines a yes (a group yes counts for its group). Silence, or "looks fine" with no yes, does not count: ask once more in different words.
5. After each correction round, write what was confirmed and commit a checkpoint. Each confirmed line becomes a sentence in the section of the page it belongs to, as `CONVENTIONS.md` says under "Pages" and `house-voice` says for prose: the source's link on the words that rely on it, the wording saying how sure it is ("the agreement summary says…" for a fact, "Partnerships expects…" for an assumption). Contracts, unknowns, parties and stored value keep their fact bullets, each opened by a sentence. Say it in your own words. Never copy document text into the vault. The capture line keeps the line's state.

   Decide each line's state from where it comes from:
   - A line from an `exists` or `repo` source is a `fact`, with `sources: [SRC-nn]` on the page or `- **Source:** SRC-nn` on a contract.
   - A line from an `intends` source is an `assumption`, however sure it sounds. "Ready in Q4" in a deck is a plan, not a fact.
   - A line about the future ("will", "planned", "by Q4", "ready in") is an `assumption`, whatever its source's `Kind`.
   - A line the user knows first-hand is a `fact` only once it has its own row in `sources.md`, with the user's handle as Owner and today's date. `first-hand` is not a registered `Kind`, so give the row `Kind: exists` and Location `first-hand: <handle>`. That row is the source the fact cites.
   - Claude's general knowledge is never a source.
   - Two sources that disagree become one unknown naming both, with an owner handle and an ask-by date, per `MODES.md`.

   Each fact written also gets a capture line and a `## Changes` row. Mark that capture at once: `→ keep: [[<page>#<heading>|<ID>]] (fact)`. Close leaves facts already written alone.

   Type the subject. A confirmed line that names an outside organization, or value held for customers such as points, credits, balances or deposits, gets its typed section on `03-context-and-scope.md`: `### PTY-nn <name>` with `**Relationship:**` and `**Agreements:**`, or `### SV-nn <name>` with `**Holder:**` and `**Owner:**`, as `CONVENTIONS.md` says. The catalog's questions fire only on typed subjects, so an untyped one is a question nobody will be owed.
6. Read the open unknowns on `11-unknowns-and-risks.md` against the confirmed lines. For each one a confirmed line answers, show the answer and its source and ask for a yes, then resolve it as `MODES.md` says under "Unknowns". Say which unknowns the sources leave open. Then run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/planner questions --open --json` and do the same for its copies and reviewer questions: for each one a confirmed line answers, show the answer and its source, and on a yes capture it starting with the copy or `R-` ID, such as `Q-DAT-02@APP-coach: the privacy review says…`, so close writes its `answered` row with that source. A concern cell the answer settles, `unchanged` or `n/a`, is written now as `CONVENTIONS.md` says under "Concern cells and waivers".
7. Once the confirmed lines are written, run the review checkpoint in `${CLAUDE_PLUGIN_ROOT}/references/REVIEW.md`, with the checkpoint "after the read-back" (the "Here's what I think exists" step, once its lines are written) and the confirmed lines as its focus. Show the digest as REVIEW says and capture what they take. When the lead says yes to an existence question, such as "does anyone hold value on customers' behalf?", type the subject as step 5 says, then run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/planner questions --subject <ID>` and show the questions the new subject now owes.
8. Finish with a short Dump & Diverge segment: ask what the documents leave out, the questions a careful reader would still have after reading them all, and capture the answers. Add `dump` to the record's `modes`.
9. When the lead says they are done, close as `${CLAUDE_PLUGIN_ROOT}/references/START.md` says under "Closing a session".
